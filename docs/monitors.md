# Monitors

## Match monitors by description, not connector name

Monitors connected through an MST dock or hub (here, the middle Dell P2414H)
get a **new connector name on every replug**: `DP-6` → `DP-7` → `DP-8` …
The kernel allocates a fresh MST connector each time, so the name cannot be
pinned. Anything keyed on the port name then silently stops matching: the
workspaces assigned to that monitor land elsewhere, hyprpaper misses it, and
the layout falls back to `highres,auto`.

The EDID description (`make model serial`) never changes, so every monitor
reference uses `desc:` instead:

```
$monitor1 = desc:Dell Inc. DELL S3221QS 6JQPTB3      # Left   - Dell 4K
$monitor2 = desc:Dell Inc. DELL P2414H 36WJX5CQ36PB  # Middle - Dell 1080p
$monitor3 = eDP-1                                    # Internal panel (name is stable)
```

Get the descriptions from `hyprctl monitors` (the `description:` line).

### Where monitor names live

| File | Notes |
| --- | --- |
| `config/hypr/hyprland/monitor-vars.conf` | Single source of truth. Values run to end of line or `#`, so spaces are fine. |
| `config/hypr/hyprland.lua` | Parses `monitor-vars.conf` into `_G.MONITORS` for `lua/workspaces.lua`. |
| `scripts/apply-monitor-vars.sh` | Generates `hyprpaper.conf` and `monitor-env.sh` from it (both gitignored). |
| `config/hypr/monitors.lua` | Layout (mode, position, scale). Generated by nwg-displays, then switched to `desc:` by hand. |
| `config/hypr/lua/input.lua` | Tablet mapped to `DP-1`. Fine while the 4K stays on a direct port. |

**nwg-displays caveat:** saving from nwg-displays rewrites `monitors.lua` with
port names. Enable its "use descriptions" option first, or re-apply `desc:`
afterwards.

### Recovering without a reboot

After changing any of the above, or if a replug left things misplaced:

```bash
~/hyprconfig/scripts/apply-monitor-vars.sh  # regenerate hyprpaper.conf + monitor-env.sh
hyprctl reload                  # re-read monitor/workspace rules
hyprctl configerrors            # should be empty
pkill hyprpaper; setsid hyprpaper >/dev/null 2>&1 &
```

Workspace rules do not move workspaces that already exist. Move them by hand
(Hyprland 0.56+ Lua dispatcher syntax):

```bash
hyprctl dispatch 'hl.dsp.workspace.move({ workspace = 10, monitor = "desc:Dell Inc. DELL P2414H 36WJX5CQ36PB" })'
```
